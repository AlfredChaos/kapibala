# 07 · C 组（选做）与交付物

> 来源：原文 §3.C + §5。除【解读】块外，均为原文规范的无损重组。

## C 组（选做）

### C1 媒体文件

- `message` 事件带 `mediaUrl` 时，把文件**下载到本地 `media/`**，路径记在消息的 `localFilePath`。
- 定期删除超过 N 天（**可配，默认 30**）的文件。
- 删除后**不能留下指向已删文件的记录**。
- **仍被运行中的 agent run 用到的文件不删**。

### C2 接入真实 LLM

- 用 Claude 或 Gemini（**自备 key**）实现一个**独立服务**，对外接口与 §2.2 **完全相同**。
- 后端**只改 `AGENT_URL`** 即可切换。

### C3 端到端测试

- Playwright：登录 → 打开群 → 看到 agent run 的步骤。

## 交付物（原文 §5 + 题头）

| 项 | 要求 |

| 时限 | 收到题目后 **48h 内**提交；题量较大，**做到哪算哪** |
| 方式 | GitHub **public repo** 链接，或含 `.git` 目录的压缩包 |

## 【解读】C 组的取舍建议

- **C2 信号价值最高**（对 AI 全栈岗位）：证明你理解 tool-use 协议本身，而不是只会写 mock。实现要点是把 LLM 的原生输出**适配成 §2.2 的严格形状**（恰好一个块、stop_reason 一致），并且主动复刻坏行为开关以便自测。
- **C1 是经典后台任务题**：下载幂等（同一 msgId 不重复下载）、删除与引用一致性、运行中 run 的文件保护——工作量可控。
- **C3 注意你自己的全局测试策略**：E2E 属于真实浏览器驱动，如需编写请先确认投入产出；笔试语境下一条"登录 → 群详情 → 看到 run 步骤"的冒烟脚本即可，不必铺开。
- 「做到哪算哪」+ 评分未知 → 建议**宁可 A/B 组做到扎实可演示，不要为 C 组牺牲 A 组正确性**；README 里明确列出已完成 / 部分完成 / 未做，以及每个 S 场景的演示方式。
