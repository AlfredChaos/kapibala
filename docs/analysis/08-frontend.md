# 08 · 前端需求

> 来源：原文 §4。除【解读】块外，均为原文规范的无损重组。

## 技术约定

- React 18 + TypeScript + **Vite**；UI 库、状态库自选。
- **不需要** i18n、主题切换、响应式。

## 页面清单（5 个）

| # | 页面 | 对应需求 |
|---|---|---|
| 1 | 登录 | A6 |
| 2 | 账号列表 | A6 |
| 3 | 群详情 | A6 |
| 4 | Agent 运行详情 | B4 |
| 5 | 序列运行 | B1 |

### 1. 登录

- `viewer` 登录后**看不到写操作按钮**。

### 2. 账号列表

- 显示状态。
- **「标记离线」「重连」「释放账号」三个按钮只在对应转移合法时出现**。
- `viewer` 看不到这些按钮，**直接调接口也得到 `403`**（即前端隐藏只是展示层，权限由后端保证）。

### 3. 群详情

- 成员列表（含 role）。
- 消息时间线：「**加载更早**」（游标分页）；**实时追加**；自己的消息显示 `deliveryStatus`。
- 该群最近的 agent run 列表（状态、endReason）；`blocked` 的 run **醒目提示**。

### 4. Agent 运行详情（B4）

- 每一步的 `kind`、工具名、入参、结果摘要、审计结论、错误码。
- **协议错误步可查看原始响应体**（`rawResponse`）。

### 5. 序列运行（B1）

- 选序列、填 `vars` 和 `stepVars` → **预检弹窗**（每步每个 key 的最终取值与来源）→ 启动。
- 运行中显示进度。
- 预检不通过时显示 `stepIndex` 和 `key`。

## 【解读】实现提示

- 权限是**双层**的：按钮可见性（viewer 隐藏）+ 接口层 403。前端只需按角色渲染；后端必须兜底（A0）。
- 页面 3 的实时性 = WS `message` 事件 + 断线重连后 `sinceSeq` 补齐（B4 的 3 秒要求）；「加载更早」与实时追加并发时的游标稳定性见 A4。
- 自己消息的 `deliveryStatus` 会沿 `queued → accepted → sent` 流转，时间线上需要能原地更新（对应 `message` / WS 事件）。
- 页面 5 的预检弹窗可以直接复用后端预检逻辑的展示版（每步 `resolvedVars` + `varSources`），与 S8 的失败展示（`stepIndex` / `key`）共用一套 UI。
- 不需要响应式 / 主题 / i18n → 可以把精力全部放在状态正确性上（deliveryStatus 流转、blocked 醒目提示、序列进度）。
